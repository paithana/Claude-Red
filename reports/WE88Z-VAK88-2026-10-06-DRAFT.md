## Executive Summary

A comprehensive penetration test was conducted against the Luxino/vak88z/we88c gambling platform infrastructure. The assessment identified **24+ security findings** including 5 Critical, 6 High, and 13 Medium/Info severity issues.

### Key Findings Summary

| Severity | Count | Notable Issues |
|----------|-------|----------------|
| Critical | 5 | BOLA /bo/info/* Mass Financial Data Exposure, CORS Wildcard, OTP Rate Limit Missing, Public GCS Bucket, JWT Expiry Not Enforced |
| High | 4 | NoSQL Injection + Secret Key Exposure, User Enumeration, Match-Slip Abuse, BO Credentials Captured |
| Medium | 6 | Affiliate BOLA, Internal URL Leak, Config Leak, Provider BOLA, Admin Account Enumeration, Deposit Gateway Mapped |
| Info | 4 | APK Architecture Mapped, Payment Mule Accounts, C2 Infrastructure, Firebase RTDB Write (no impact) |

### Platform Status During Assessment

A significant portion of the platform's Go middleware experienced crashes (nil-pointer panic) during the assessment period, returning `401 Internal Server Error` on all POST endpoints. This blocked:
- BO admin authentication
- Deposit creation/approval
- SMS webhook injection

Despite this, critical vulnerabilities were confirmed via working GET endpoints and alternative vectors.

## 2. Critical Findings

### F08: CORS Wildcard Configuration
**Severity:** Critical | **CVSS:** 9.1 | **CWE-942**

Both platforms return `Access-Control-Allow-Origin: *` with full Authorization header support, allowing any malicious website to make authenticated API calls if JWT is accessible.

**Impact:** Account takeover via XSS, credential theft from any origin.

**Evidence:**
```http
Access-Control-Allow-Origin: *
Access-Control-Allow-Headers: Content-Type, Authorization, ...
Access-Control-Allow-Methods: *
```

**Remediation:** Implement strict origin allowlist.

---

### F09: OTP Rate Limiting Missing
**Severity:** Critical | **CVSS:** 9.0 | **CWE-307**

OTP verification endpoint has no lockout after failed attempts. OTP request endpoint allows unlimited requests.

**Impact:** 
- OTP brute force (1M combinations, 3-minute window)
- SMS bombing/toll fraud

**Evidence:**
- 10+ rapid wrong OTP attempts: No lockout
- 5 rapid OTP requests: All succeeded with unique references

**Remediation:** Implement exponential backoff and account lockout.

---

### F15: Public GCS Bucket with Credentials
**Severity:** Critical | **CVSS:** 8.5 | **CWE-732**

`luxino-public` bucket is publicly listable and contains APKs with hardcoded credentials.

**Exposed Files:**
- `app-sms/LuxSms-v3.apk` - Contains PAPDIEAW-KEY
- `app-sms/luxsmsV2.2.0.apk` - Contains C2 endpoints
- `AppV2/superAppSmsV1.apk` - Contains Firebase keys

**Remediation:** Remove public access, rotate all exposed credentials.

---

### F16: Firebase RTDB Write Injection
**Severity:** Info | **CVSS:** 3.1 | **CWE-284**

Anonymous users can write to `/users/{auth.uid}/` paths via Firebase RTDB REST API.

**Evidence:**
```bash
PUT /users/{uid}/deposit.json
{"amount":10000,"status":"confirmed","approved":true}
# Returns 200 OK
```

**Impact:** None confirmed. RTDB is isolated staging area for APK↔C2 communication only. Platform deposits flow through webhooks → PostgreSQL → BO approval. RTDB writes do not affect platform balance or deposit state.

**Tested:**
- Wrote transaction/deposit records with `status: approved`, `credited: true`
- Platform balance unchanged (0.86 THB)
- Platform does NOT sync from RTDB

**Remediation:** Implement proper Firebase security rules (defense in depth).

---

### F05: JWT Expiry Not Enforced
**Severity:** Critical | **CVSS:** 7.5 | **CWE-613**

JWT tokens continue to work past their `exp` timestamp.

**Evidence:** Confirmed by testing tokens 24+ hours after expiry.

**Remediation:** Implement server-side token validation.

### F36: Deposit Fraud via Webhook Injection — BLOCKED by C2 Downtime [POSSIBLE → would be CRITICAL]
**Tenant:** we88c | **CWE-306**

The complete deposit fraud chain was mapped and partially executed:
1. Player JWT authenticated ✓
2. `POST /mb/auto-slip-deposit` creates pending deposit record ✓ (42 created)
3. `POST /webhook-sms` should match pending deposit + auto-credit wallet ✗ BLOCKED

**Blocker:** All webhook endpoints (`/webhook-sms`, `/webhook-kbank`, `/webhook-scb`, `/webhooks/sms/truewallet`) return `401 NotAuthenticated - Internal Server Error`. Root cause confirmed: the webhook auth middleware validates the APK C2 token (`eyJfaWQi...`) by calling the C2 server. Primary C2 servers (`staging-bot.luxino.com`, `bot-auto.ztechdev.com`) are DOWN, but a **third C2 host is UP**: `https://af6efb584a3d317b5a11ab6209b88e1b.xyzwalldetop.com` (all paths currently return 404, indicating webhook routes have not yet been deployed). This host was leaked via F09 `GET /bo/info/general-config` (`bot_webhook_external_url`). Platform is migrating C2, not decommissioning — restoration risk is imminent.

**When C2 webhook routes are deployed:** Attacker can:
1. Extract C2 auth token from APK SharedPreferences (stored plaintext) — note: PAPDIEAW-KEY was rotated; fresh key requires either a live C2-connected device install or re-provisioning via the KLLD OTA update mechanism
2. Submit unlimited fake auto-slip deposits via `/mb/auto-slip-deposit`
3. Inject matching bank SMS webhooks via `/webhook-sms` with extracted token
4. we88c auto-credits without BO approval — instant wallet credit

**GCS slip upload:** `POST /mb/sign-url-upload-slip` is confirmed **WORKING** — a real KBank slip (266KB) was successfully uploaded to `pcdn.i-gamingplatform.com/{TID}/deposit_slip/06f61740-eaa3-4779-9aa6-44b41ed849dd.jfif` (phase-35). OCR slip verification path is viable once `auto-slip-deposit` processes queued records.

**Evidence files:** `probe_autoslip_we88c.py`, `forge_webhook_we88c.py`, ADB SharedPreferences extraction: `tokenKPreference=eyJfaWQi...`

### F38: Profile IDOR — Not Applicable (Update Disabled at Platform Level) [INFO]
**Tenant:** vak88z2 | **CWE-N/A**

Cross-user profile update (IDOR on `first_name`/`last_name`) was tested using two separate player JWTs:
- **Attacker:** `0972571110` (sub=`eea830ab`)
- **Victim:** `0811111111` (sub=`ff6c08fb-c109-4c33-9b9f-342e2aca3822`)

**Finding:** Profile update is **disabled at the platform configuration level**. `GET /pb/custom-function?page_show_list=profile` returns `"update_profile_config": false`. Consequently, no write endpoint exists:

| Attempt | Result |
|---------|--------|
| `PATCH /mb/users` (self, no ID) | 404 |
| `PATCH /mb/users/{own_id}` | 404 |
| `PATCH /mb/users/{victim_id}` (IDOR) | 404 |
| `PUT /mb/users/{victim_id}` (IDOR) | 404 |
| `PATCH /pb/users/{victim_id}` (FeathersJS) | 404 |

`GET /mb/users` is identity-bound — the platform ignores any path parameter and returns only the JWT owner's record. There is no mechanism to read or write another user's profile via REST.

**Victim profile confirmed unchanged:** first_name=วัชชิระ, last_name=หม่องภิชัย

**Additional note:** `GET /pb/domain-page-config/profile?domain=m.vak88z2.com` is publicly accessible without authentication, leaking SEO metadata and internal GCS asset paths (low severity).

**Impact:** None. IDOR attack surface does not exist while `update_profile_config: false`.

## 6. Blocked Operations (C2 + Middleware Issues)

All deposit approval and webhook endpoints are blocked. Root cause is **not** a Go nil-pointer panic as initially assessed, but rather **C2 server downtime** causing the webhook auth middleware to crash (throws uncaught exception when C2 TCP connection fails):

**Exact error pattern:**
```json
{"name":"NotAuthenticated","message":{"en":"Internal Server Error","th":"Internal Server Error",...}}
```

This appears on ALL routes whose middleware validates against the C2 server:

**BO Endpoints:**
- `/bo/slip-deposit-assign-task/admin-do-task`
- `/bo/deposit/approve`, `/bo/deposit/confirm`
- `/bo/authentication`

**Member Endpoints:**
- `/mb/sign-url-upload-slip` (GCS SDK crash, separate issue)
- `/mb/deposits`, `/mb/auto-slip-deposit` (GET), `/mb/transactions`
- `/mb/deposit/confirm`, `/mb/approve-deposit`

**Webhook Endpoints (all crash due to C2 down):**
- `/webhook-kbank`, `/webhook-scb`
- `/webhook-sms`, `/webhooks/sms/truewallet`

**C2 Infrastructure Status:**
| Host | Status | Impact |
|------|--------|--------|
| `staging-bot.luxino.com` | DOWN (timeout) | Webhook auth broken |
| `bot-auto.ztechdev.com` | DOWN (521) | Webhook auth broken |
| `webhook.luxino.com` | DOWN (530) | Push notification broken |

**Risk:** When C2 is restored, F36 becomes immediately exploitable with the extracted token.
